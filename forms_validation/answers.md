1. **HTML5-атрибуты валидации:** `required` (обязательное поле), `minlength`/`maxlength` (длина текста), `min`/`max` (для чисел и дат), `type="email"` (проверка формата почты), `pattern` (регулярное выражение).
2. **Разница `novalidate` и JS:** Атрибут `novalidate` отключает встроенную браузерную проверку, чтобы мы могли написать свою (кастомную) на JavaScript и показывать красивые сообщения об ошибках. Отключение валидации через JS — это просто игнорирование проверок, что может привести к отправке некорректных данных.
3. **Связь `<label>` и поля:** Атрибут `for` в теге `<label>` должен совпадать с `id` поля ввода. Это важно для доступности: при клике на текст подписи фокус переходит в поле, а скринридеры зачитывают название поля.
4. **Типы `input`:** `email` (для почты), `tel` (для телефона), `password` (скрывает символы), `date` (для дат), `number` (для чисел).
5. **Атрибут `pattern`:** Позволяет задать регулярное выражение, которому должно соответствовать значение. Используется для сложных форматов (например, номер телефона или требования к паролю).
6. **События JS:** `input` (срабатывает при каждом изменении, используется для очистки ошибок), `blur` (срабатывает при потере фокуса, используется для проверки заполненности), `submit` (для проверки всей формы перед отправкой).
7. **Доступность ошибок:** Сообщения об ошибках должны быть связаны с полем через `aria-describedby` и находиться в контейнере с `role="alert"`, чтобы скринридеры сразу зачитывали их при появлении.
8. **`fieldset` и `legend`:** Они группируют связанные поля (например, «Личная информация»). Это помогает визуально разделить форму и дает скринридерам понимание контекста.
9. **Кастомная валидация:** Пишется в JavaScript. Например, для проверки пароля мы берем значение из двух полей и сравниваем их через `if (pass1 !== pass2)`.
10. **CSS для валидации:** Используются псевдоклассы `:valid` (для зеленой рамки) и `:invalid` (для красной), а также класс `.error`, который добавляется через JS для дополнительной стилизации и анимации.
